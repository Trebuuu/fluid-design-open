01 · Form with validation

A form that says what is wrong.

It stays quiet while you type, speaks when you leave a field, and on submit takes you straight to the first thing that needs a look. Try an empty project name, a runner address without its port, then fix them.

Add a project

It joins the workspace on its next run.

Letters, numbers, dots and underscores.
From 1 to 200 a day.
Host and port, for example 10.0.0.8:1080.

What the form knows

  • Project nameUntouched
  • Daily run capUntouched
  • Runner addressUntouched

An error appears when you leave a field, and clears the moment the value is right.

When to use

Any time people type something the product must trust: a project, a limit, an address. If a wrong value costs nothing, skip validation and let the product correct it quietly.

The rules

  1. Label above, help below; the error replaces the help, in the same place.
  2. Judge a field when it is left, not on each keystroke; once it is wrong, clear the error the moment it is right.
  3. Say what to do, not what went wrong: “Add the port, for example :1080.”
  4. On submit, count the problems in one banner, link each field, and move focus there.
  5. Success is shown where the form was, and confirmed once more with a toast.

Markup

<form novalidate>
  <div class="banner banner-inset banner-bad" role="alert" tabindex="-1" hidden>
    <span>2 things need a look.</span>
  </div>
  <div class="form-field">
    <label for="handle">Project name</label>
    <input class="field" id="handle"
           aria-describedby="handle-help handle-err">
    <span class="field-help" id="handle-help">Letters, numbers…</span>
    <span class="field-error" id="handle-err" hidden></span>
  </div>
  <button class="btn btn-primary btn-l">Add project</button>
</form>
function show(input, message) {        // message = '' when valid
  const err = document.getElementById(input.id + '-err');
  input.setAttribute('aria-invalid', message ? 'true' : 'false');
  err.textContent = message;
  err.hidden = !message;                 // .field-help hides itself
}

Built from fields, banners and toasts, and a loading button.

02 · Search with results

Results as you type.

Every keystroke narrows the list; the matching letters are marked; the count is spoken, not just shown. Scope chips cut the list by kind. Arrow down from the field into the results; Escape clears.

When to use

When there are more things than fit on one screen and people know roughly what they are called. For browsing without a name in mind, use filters and sorting instead.

The rules

  1. Filter as people type; no search button, no page reload.
  2. Mark the matched letters, so it is clear why a result is there.
  3. Announce the count in a polite live region.
  4. An empty result says what was searched and how to widen it.
  5. Escape clears the field; a second Escape leaves it.

Markup

<div class="search">
  <input type="search" aria-label="Search" aria-controls="results"
         aria-describedby="count">
</div>
<div role="radiogroup" aria-label="Show">
  <button class="chip chip-s" role="radio" aria-checked="true">All</button>
  <button class="chip chip-s" role="radio" aria-checked="false">Runs</button>
</div>
<p id="count" role="status" aria-live="polite">4 results</p>
<div id="results">
  <p class="list-header">Review queues</p>
  <ul class="list list-inset">
    <li><a class="row" href="…"><span class="row-title">
      sample.<mark>we</mark>b</span></a></li>
  </ul>
</div>

Built from search, chips, rows and the empty state.

When to use

For preferences people set once and revisit rarely. Group by what people think about together — pacing, notifications — not by how the code is organised.

The rules

  1. A switch acts the moment it flips; nothing waits for a Save button.
  2. A row that opens a screen shows its current value, then the chevron.
  3. The pushed screen slides in from the trailing edge; the old one shifts back by a third.
  4. Back names where it goes (“Settings”), not just “Back”.
  5. Headers in title case; footers explain the consequence, once.

Why a phone

Settings live on the companion app, so the pattern is shown where it will run. The same list classes render at desktop density in the console; nothing here is phone-only.

04 · Destructive confirmation

Ask once, and only when it matters.

Pausing a review queue is undone as easily as it is done, so it just happens. Deleting one is not: the trash button becomes the question, grown out of the glass it was pressed on, and melts back into it if you cancel.

sample.api

Reviewers of · basil

8 of 8 completed todayHealthy

#docs

Label · cobalt

3 of 8 completed todayThin

When to use

Only for actions that cannot be undone or that throw away someone’s work. Everything reversible happens at once and offers Undo in a toast.

The rules

  1. The title asks the exact question: “Delete sample.api?”
  2. The message states the consequence in one sentence, including what is kept.
  3. The destructive button names the verb; Cancel is always there, and Escape means Cancel.
  4. The alert grows out of the button that asked, and returns into it.
  5. After it is done, a toast confirms — with Undo whenever undo is possible.

Markup

<!-- a glass control over media, with a stable id to morph from -->
<button class="btn btn-glass btn-icon" data-lg3 data-lg3-interactive
        data-lg3-id="del-api" aria-label="Delete sample.api">
  <i data-sym="trash"></i>
</button>
button.addEventListener('click', async (e) => {
  const ok = await UI.alert({
    title: 'Delete sample.api?',
    message: 'Its ledger rows stay. Future runs stop reaching it.',
    from: e.currentTarget,               // same data-lg3-id: a morph
    actions: [
      { label: 'Cancel', value: false, role: 'cancel' },
      { label: 'Delete', value: true, role: 'destructive' }
    ]
  });
  if (ok) remove(card);                  // then a toast with Undo
});

Built from UI.alert and UI.toast, glass buttons and cards with media.

05 · Overlay flow

A sheet that grows from its button.

A short task that should not lose your place. The sheet opens at half height, as glass you can see the page through; pull it up and it turns opaque and anchors to the edges. Flick it down to dismiss.

The last runs3814 came back empty, 1 never started
Completed1,222of 1,904 queued
Inside runs12.6 sa completed task

When to use

For a task that belongs to what is on screen and takes under a minute: set up a run, filter a list, edit one thing. Longer work gets its own page; a single decision is an alert.

The rules

  1. Partial height is inset glass; full height is opaque and meets the edges.
  2. Dim the page only when the sheet interrupts; a parallel task leaves it lit.
  3. Close on the leading edge, Done on the trailing edge, never a third.
  4. The grabber cycles the detents and works with a keyboard.
  5. One sheet at a time. Escape closes the topmost surface.

Markup

<button class="btn btn-glass btn-primary" data-lg3
        data-sheet-open="new-run">New run</button>

<div class="sheet" id="new-run" data-lg3 data-detents="medium large"
     data-sheet-dim aria-labelledby="new-run-title" hidden>
  <button class="sheet__grabber" aria-label="Sheet size"></button>
  <div class="sheet__header">
    <button class="sheet__close" aria-label="Close" data-sheet-close>…</button>
    <h2 class="sheet__title" id="new-run-title">New run</h2>
    <button class="sheet__done" aria-label="Done" data-sheet-close>…</button>
  </div>
  <div class="sheet__body">…</div>
</div>
CHROME.sheet.open(sheet, { from: button, detent: 'large' });
sheet.addEventListener('chrome:sheet', e => log(e.detail.detent));

When to use

Every list and table, without exception. Design the empty and broken states first: they are what a new project sees on its first day.

The rules

  1. Loading shows the shape of what is coming, not a lone spinner, and carries aria-busy.
  2. Empty says what belongs here and gives the one action that fills it.
  3. Error says what failed, what was not lost, and offers a retry.
  4. Success replaces the loading shape in place; a quiet banner says it is fresh.
  5. Every state keeps the same frame, so nothing jumps.

Markup

<div id="loading" role="tabpanel" aria-busy="true">
  <ul class="list list-inset" aria-hidden="true">

07 · Onboarding

Three steps, then out of the way.

Each step asks for one thing. The pages travel on a spring you can interrupt, the page dot stretches into a pill, and the last step ends in a tick that draws itself.

9:41

Connect a runner.

Orbit runs your team’s jobs on a runner you own. The runner does the work; this app shows you every step it took.

Choose what to review.

Pick the review queues that look like yours.

Set your limits.

The cap is counted on what completes, every day.

  • Runs a day
    24

You’re set.

The first run starts within the hour. You can change any of this in Settings.

Continue, Back and the arrow keys all move it.

When to use

Once, on first launch, when the product cannot work until it knows a few things. Never to tour features people can find on their own.

The rules

  1. Three steps at most, one question each; every step can be skipped or revisited.
  2. The page travels on a spring and can be reversed mid-flight.
  3. The progress dot stretches into a pill: where you are, at a glance.
  4. Under reduced motion the pages cross-fade; nothing slides.
  5. Finish with what happens next, and where to change it later.

The motion

The track moves on --sp-move (.46 s, bounce .18) as a CSS transition, so a second press retargets from wherever it is. The tick draws in 600 ms on --ease-out-cubic.

Markup

.onb-track {
  display: flex;
  translate: calc(var(--step) * -100%) 0;
  transition: translate var(--sp-move-ms) var(--sp-move);   /* interruptible */
}
.onb-dots i { width: 8px; transition: width var(--sp-snappy-ms) var(--sp-snappy); }
.onb-dots i[data-on] { width: 24px; }
@media (prefers-reduced-motion: reduce) {
  .onb-track { transition: none; }       /* slides cross-fade instead */
}

Built from block buttons, chips, rows and the spring tokens.

08 · Notifications

The right weight for the news.

Something happened: a toast. Something is still true: a banner, in the flow, until it is not. Something needs a decision: an alert. Choose by what the news asks of the reader, never by how important it feels.

Toast

It happened.

Transient, never blocks, never asks. Stacks from the bottom.

Banner

It is still true.

In the flow, above what it affects; it leaves when the fact changes.

  • runner-01Connected
  • runner-02Offline 18 min
Alert

Decide now.

Interrupts, so it is rare: only for what cannot be undone.

Four projects are mid-run.

When to use

Whenever the product has news the reader did not directly cause, or confirmation of something that happened out of view. If people can see the change happen, say nothing.

The rules

  1. A toast is one short sentence, past tense: “Run saved.”
  2. A toast with Undo waits for its decision; others leave after reading time.
  3. Errors that need an action are banners or alerts, never toasts alone.
  4. A banner changes with the fact, then leaves on its own.
  5. Toasts are a polite live region; failures use an assertive one.

Markup

UI.toast('Run saved.', { kind: 'ok' });

UI.toast('Review queue removed.', {
  kind: 'info',
  action: { label: 'Undo', run: () => restore() }
});

UI.toast('Could not reach runner-02.', { kind: 'bad' });  // role="alert"
<div class="banner banner-inset banner-bad">
  <i data-sym="xmark-circle"></i>
  <span>runner-02 stopped answering. Its runs are paused.</span>
  <button class="btn btn-plain btn-s">Reconnect</button>
</div>

Built from toast, banner and alert and status pills.

09 · Data table

A table that stays in its frame.

The header stays pinned while the rows scroll under it. Sort by any number, select rows for a bulk action, or open a row’s own menu for the rest.

Review queues

16 review queues

0 selected
Route State Actions

When to use

When people compare rows by their numbers. If each item is read on its own, a list of rows or cards reads better, especially on a phone.

The rules

  1. The table scrolls inside its own frame; the header is sticky in that frame.
  2. Numbers are end-aligned in tabular digits; missing values are a dash, never zero.
  3. Sortable headers are buttons, and aria-sort says which way.
  4. Selection reveals a bulk bar with a count; it hides again at zero.
  5. Row actions live in the row’s own menu; destructive ones come last.

Markup

<div class="table-scroll" style="max-height: 460px" tabindex="0">
  <table class="table table-sticky table-hover">
    <thead><tr>
      <th><input class="check" type="checkbox" aria-label="Select all"></th>
      <th class="num" aria-sort="descending">
        <button>Completed</button></th>
      <th><span class="sr-only">Actions</span></th>
    </tr></thead>
    <tbody><tr>
      <td><input class="check" type="checkbox" aria-label="Select"></td>
      <td class="num">7</td>
      <td><button class="btn btn-icon btn-s" data-menu="row-1"
                  aria-label="Actions">…</button></td>
    </tr></tbody>
  </table>
</div>

When to use

In a product with more places and actions than a sidebar can hold, for people who return every day. It is an accelerator: everything in it must also be reachable without it.

The rules

  1. The pill morphs into the panel and back; it never fades in.
  2. Focus lands in the field; arrows move the highlight; Enter runs it.
  3. Group by destination and by action; show shortcuts where they exist.
  4. Match on keywords as well as labels, and say so when nothing matches.
  5. ⌘K opens it from anywhere; Escape closes it into the pill.

Markup
