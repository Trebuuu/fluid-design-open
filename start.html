Live, at 402 px. The phone renders the code as written; the canvas is painted, the platter bends it.

  1. Tone before paint. The head script reads the reader’s choice, then the host, then the system, so the first frame is already the right tone.
  2. Tokens, then one palette. fg3-tokens.css first, then exactly one fg3-color*.css. Everything after them reads roles.
  3. Bands, not sections. .band with data-band story, utility or stage carries the band padding; a stage band is dark before any script runs.
  4. Scripts last, in order. geom.js before lg3-core.js, and fg3.js before the modules it mounts.
  5. One boot. FG3.boot() paints the art, builds the glass and arms the reveals. No module mounts itself.

Pick a palette

Your colour. One link.

A palette is a generated file, fitted in OKLCH from your accent and checked for contrast in both tones. Swap the link and every role follows: fills, links, focus rings, charts and the glow under the primary.

Boot and tone

Boot once. The tone follows the reader.

The head snippet paints the first frame in the right tone; FG3.boot() takes over from it. The reader’s choice wins, then the author’s data-tone, then the host’s data-theme, then the system.

<!-- In <head>, before the stylesheets -->
<script>try{var d=document.documentElement,t=localStorage.getItem('fg3-tone');
if(!d.hasAttribute('data-tone')){d.setAttribute('data-tone',t||d.getAttribute(
'data-theme')||(matchMedia('(prefers-color-scheme: dark)').matches?'dark':
'light'));d.setAttribute('data-tone-auto','')}}catch(e){}</script>

<!-- At the end of <body>, after the last script -->
<script>FG3.boot();</script>
var state = FG3.boot();      // idempotent: a second call returns the same state
state.mounted;               // ['ART3', 'LG3', ...]: whatever the page loaded
state.errors;                // any module that threw; the rest still mounted

FG3.setTone('dark');         // 'light' | 'dark' | 'auto', remembered as fg3-tone
FG3.getTone();               // {tone: 'dark', mode: 'dark', source: 'user'}
document.addEventListener('fg3:tone', function (e) {
  console.log(e.detail.tone, e.detail.source);
});
<!-- A band can carry its own tone; a stage band is dark without being told -->
<section class="band" data-band="utility" data-tone="dark">…</section>

<!-- Pin a page to one tone only when it must be (a dark-only console) -->
<html lang="en" data-tone="dark" data-tone-lock>

The first traps

Eight things that fail without an error.

Each of these has cost a builder an afternoon. The symptom is the question; the fix is one press away.

1The glyphs are empty, the art is blank and nothing moves.

No module mounts itself. Call FG3.boot() once, after the last script. It paints the art, builds the glass, expands the symbols and arms the reveals — and a module that throws is recorded in state.errors instead of stopping the rest.

<script src="assets/fg3.js"></script>
<!-- … the other modules … -->
<script>FG3.boot();</script>
2The glass is a flat, grey box.

Something above it has become a backdrop root: opacity below 1, a filter, a mask or a mix-blend-mode on an ancestor, often a fade-in. Animate transform on ancestors, never opacity, and bring glass in with LG3.materialize(el). Then check there is something under it to bend.

LG3.materialize(document.querySelector('.toolbar'));   // not el.style.opacity = 1
3The viewer’s light and dark switch does nothing.

data-tone on <html> is an author pin, and an author tone beats the host’s data-theme. Leave <html> bare and let the head snippet choose. Pin only a page that must be one tone, and then add data-tone-lock on purpose.

4The accent colour never shows.

A palette generated at run time with PALETTE.install() lands in the head, before an Artifact’s body-linked stylesheets, and loses the cascade while reporting success. Link the generated file right after the tokens, and link only one.

<link rel="stylesheet" href="assets/fg3-tokens.css">
<link rel="stylesheet" href="assets/fg3-color.css">
5Small grey text fails the audit.

--label-3 and --label-4 are 3:1 roles, for 19 px semibold or 24 px text and for glyphs. Anything at 17 px or below takes --label-2, and text on a fill takes --label-2-on-fill.

6Glass added from a script stays flat.

The engines do not watch the DOM. After inserting a glass host, apply it; after inserting a subtree, refresh corners and radii and mount the modules that own what you added.

LG3.apply(host);          // one new [data-lg3]
FG3.refresh(root);        // continuous corners and concentric radii
SYM.mount(root);          // then whichever modules own the new markup
UI.mount(root);
7Scroll choreography never runs in a narrow window.

That is the capability gate: windows between 481 and 734 px, a small desktop window, reduced motion and text zoom get the base experience, with every element in its final state. Add ?fd-enhanced to the URL to test the choreography anyway; html.fd-enhanced or no-fd-enhanced and data-fd-cause say which you got.

8The published page is unstyled, or its dashes are garbled.

An Artifact serves only the files in its map, a republish replaces the whole set, and the host may drop the charset. Build with the publishing tool, pass the whole files map every time, and keep displayed non-ASCII as entities such as &mdash;. The build escapes every file and refuses anything it missed.

node tools/artifact-build.mjs     # dist/ and dist/publish-map.json, or a refusal with the reason
